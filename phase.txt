Phase 5 Plan (Intelligence Engine)

5.1 Sector Intelligence Refresh: Recompute sector_summaries from trusted reports instead of static seed data. Use trust metadata (confidence components, verification state, dedupe clusters) to update threat, opportunity, and confidence scores per sector. Persist via cron/API so Supabase stays the single source.
5.2 Route Safety Model: Introduce a route_summaries table (origin, destination, corridor state) fed by nearby sector stats + fresh report clusters. Compute safe, volatile, hostile flags plus reasoning JSON used by UI and AI advisor.
5.3 Pack/Faction Intel View: Add optional faction/pack grouping on reports so we can aggregate verified intelligence per faction. Expose a /api/intel/packs endpoint that returns the top observations and confidence per faction for future in-assembly sharing.
5.4 Advisor-Ready Output: Standardize a structured_intel payload combining sectors, routes, and pack intel. Store snapshots (for Walrus later) and use them in the Next.js UI so Phase 6’s AI advisor can consume the same schema.
5.5 Automation Hooks: Define lightweight jobs/endpoints (POST /api/intel/recompute) that trigger recomputation, ensuring we can run it locally, via Supabase cron, or inside the assembly runtime.
