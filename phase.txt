Verify Notifications & Preferences

Start the stack

pnpm --filter @gin/api dev (or npm run dev inside api) to boot the Fastify server at http://localhost:4000.
pnpm --filter @gin/web dev (or npm run dev inside web) to serve the Next.js frontend at http://localhost:3000.
Ensure Supabase credentials/secrets are set so the API can reach the database.
Seed/confirm auth context

In the web app, connect your wallet (or whatever mechanism populates ProfileContext) so the client has a valid profileId. Watch the browser console for the “Profile connected” log to ensure API requests include the X-Wallet-Address header.
Call /api/notifications/latest

From a REST client (curl/Postman/Thunder Client) hit GET http://localhost:4000/api/notifications/latest?limit=8&profileId=<PROFILE_UUID>&sector=Jegou%20Relay (sector optional).
Confirm the JSON response includes both notifications and worldSignals arrays and that filtering respects sector/profile preferences.
Call /api/profiles/preferences

GET http://localhost:4000/api/profiles/preferences?profileId=<PROFILE_UUID> with the same wallet header if needed.
Verify the payload reflects the latest lastKnownSector, alertOptIn, and timestamps.
Test UI controls

In the running web app, open the Notifications panel. Use the new “Focus Sector” form (or assistant panel field) to update the sector and toggle alert opt-in.
Submit; you should see the toast/status message change and the form disable while saving.
Reload the page or call step 4 again to confirm the Supabase row persisted.
Validate downstream filtering

With the updated preferences, re-run step 3 without a sector query param; the API should infer the sector from the stored preference and return location-matched notifications plus world signals.
Observe the Notifications panel showing the filtered feed along with the world signal cards. Tapping “Focus Sector” on a signal should populate the form with that sector and, after saving, narrow the feed.
Optional automation checks

Submit a quick report or modify tables in Supabase to ensure new notifications/world signals appear and that the client automatically refreshes (or refresh manually) to see them.
Keep browser dev tools open to confirm no network errors and that the assistant/chat panel also references the live world signal data when you prompt it with the focused sector.
